Changelog for Msquared Toolbox
==============================

Version 1.0.4 — 23 Oct 2026
---------------------------
Fixed (class and MEX)
  - z0x/z0y are now signed: distance from the waist to the
    measurement plane, positive downstream of the waist (z0 < 0
    for a focusing beam, opposite in sign to Rx/Ry). Previously
    the per-slice z0 was always positive.
  - pulse_z0x/pulse_z0y now use the harmonic-sum R instead of the
    first curvature-removal pass only (was off by ~1% and had the
    opposite sign to the per-slice z0).
  - Vector xgrid/ygrid inputs now work in any orientation; a column
    x with a row y (or the reverse) used to crash the class.
  - meshgrid(x,y) grids now raise a gridOrientation error. They
    used to swap the x and y results without warning. Use
    ndgrid(x,y) or meshgrid(y,x).
  - calculate_second_moment works again (its arguments block named
    the class without the beam. namespace) and accepts vector grids.
  - MEX checks that xgrid/ygrid sizes match the field.

Removed
  - Class results.z0x2/z0y2 (replaced by the signed z0x/z0y).

Version 1.0.3 — 29 Jun 2026
---------------------------
Performance
  - Added inner OpenMP parallelism inside compute_slice() for
    single-slice / few-slice large-grid cases (threshold 65536
    pixels). Nt=1 speedup on 256×256 grids improved from ~1.9×
    to ~4.3× on Windows/MinGW.
  - Inner OpenMP is auto-disabled when the outer parallel slice
    loop is already active, avoiding thread oversubscription.
  - Spatial/k-space moment reductions and curvature-removal phase
    multiply are now parallelized inside each slice.

Build
  - Added MEX_PROFILE-gated timers for standard-mode FFT,
    slice loop, and output build. Use compile_mex(true) to
    enable profiling output.

Version 1.0.2 — 28 Jun 2026
---------------------------
Fixed
  - Fixed flattened_Exyz shape: now returns 3D Nx×Ny×N3 array
    matching beam.Msquared().calculate() (was incorrectly 2D).
  - Fixed msquared_auto.m: exist() returns 0 for namespaced MEX
    files; now uses which() to correctly detect compiled binaries.
    Previously caused silent class fallback = zero speedup.

Build
  - compile_mex.m now supports Windows, Linux/WSL, and macOS.
  - WSL/Linux default uses MKL via mexCallMATLAB (simpler, no
    extra lib deps; ~1.5x speedup). FFTW path kept as commented
    option for benchmarking.
  - Windows uses direct FFTW via libmwfftw3.lib (~4x speedup).
  - Ships .mexw64 in .mltbx for Windows out-of-box use. macOS
    and Linux users run compile_mex after install.
  - Source moved to +beam/private/msquared_mex.cpp.

Docs
  - README updated with platform-specific FFT paths.
  - All examples use msquared_auto.m for graceful fallback.
  - New benchmark_fftw_sweep.m for Nt sweep analysis.

Version 1.0.1 — 28 Jun 2026
---------------------------
Fixed
  - Fixed pulse_flat z0x/z0y sign and formula to match MATLAB
    class (now uses k0^2*wxsq/(Rx[0]*wkxsq) etc).

Removed
  - Removed msquared_calculate_mex.cpp and all references.
    All functionality consolidated into msquared_mex.cpp.

Version 1.0.0 — 27 Jun 2026
---------------------------
Initial release
  - beam.Msquared reference class (per-slice and fluence-based).
  - beam.msquared_mex MEX accelerator (per-slice, pulse_flat,
    second_moment modes).
  - FFTW batched 2D transforms with OpenMP spatial loops.
